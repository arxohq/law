# Working in Arxo Law

This is a standalone repository. Work and checks must succeed from its own
root, including after an ordinary clone outside any larger workspace.

- Preserve existing local changes. Do not use git stash, reset --hard or
  discard files belonging to another task.
- Keep public documentation in English. Use concrete, runnable examples and
  distinguish model results from claims about legal or scientific completeness.
- Run `npm run check` for documentation/catalogue changes. Run `npm ci --ignore-scripts`
  and `npm test` when changing runnable examples or catalogue behaviour.
- `catalog/sources.json` lists intentionally included public deliveries. Do not
  discover or publish internal workspace contents. `@arxo/docs-mcp` is excluded.
- Observe npm, PyPI and each editor registry independently. Curated website and
  community links are entry points, not successful availability observations.
- `catalog/snapshot.json`, `docs/packages.md`, `docs/ecosystem.md` and the marked
  README catalogue and community blocks are generated by `tools/catalog.mjs`. Use
  `npm run catalog:refresh` for live observations, or `npm run catalog:render`
  to render the captured snapshot. Do not fabricate a successful observation.
- Keep exact example dependencies and the lockfile. Catalogue updates must not
  automatically update the examples' dependency set.
- First-run examples accept changed facts without enforcing the original
  answer. Put fixed baseline assertions in tests. Preserve readable default
  output, parseable `--json`, explicit unknown/negative/conflict statuses and
  concrete next steps. Update the task guides with changed commands.
- No engine source is included yet. Future source imports must have an explicit
  file ownership map, preserve manually maintained files, record provenance and
  provide a documented contribution round trip. See `docs/source-availability.md`.
- Publishing this repository does not publish npm packages or validate the full
  corpus. Report only checks actually performed.
